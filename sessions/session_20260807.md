## 🎓 Key Learning Objectives Covered

### 1. Distributed Tracing Concepts

**✅ Spans** - Individual operations within a trace
```
trace_id: abc123
├─ order-service POST /orders (span 1)
├─ user-service GET /users/{id} (span 2)
├─ product-service GET /products/{id} (span 3)
└─ order-service save_to_db (span 4)
```

**✅ Traces** - Complete request journeys
```
One trace = one customer request flowing through entire system
Includes all service calls, databases, external APIs
```

**✅ Correlation IDs** - End-to-end request tracking
```
traceparent header: 00-{trace_id}-{span_id}-01
Automatically propagated across services
```

### 2. OpenTelemetry Instrumentation

**✅ Auto-Instrumentation**
- FastAPI middleware (all HTTP requests)
- Database driver (all SQL queries)
- HTTP client (all external calls)
- No code changes needed!

**✅ Manual Instrumentation**
- Create spans for business logic
- Set custom attributes
- Record exceptions
- Add events for important moments

**✅ Baggage Propagation**
- Cross-cutting concerns (user_id, correlation_id)
- Accessible in all downstream services
- No modification to intermediate services needed

### 3. Jaeger Architecture

**✅ Agent (port 6831/UDP)**
- Runs on each host/container
- Receives spans from instrumentation
- Buffers and batches spans
- Low latency, minimal overhead

**✅ Collector (port 14268)**
- Receives spans from agents
- Processes and exports spans
- Can route to multiple backends
- Handles retries and batching

**✅ Query Service (port 16686)**
- REST API for querying traces
- Web UI for visualization
- Supports complex filtering
- Real-time trace retrieval

### 4. Performance Analysis

**Identifying Bottlenecks:**
1. Open trace in Jaeger UI
2. Look at span durations (timeline view)
3. Identify slowest spans
4. Click span to see details (tags, logs)
5. Drill down into child spans

**Example Trace Analysis:**
```
Total order creation: 2500ms
├─ validate_request: 50ms (fast)
├─ get_user: 400ms (slow!) ⚠️
├─ get_product: 350ms (slow!) ⚠️
├─ reserve_stock: 300ms (ok)
├─ save_to_db: 700ms (slow!) ⚠️
└─ send_response: 5ms (fast)

→ Opportunities: Cache users, cache products, optimize DB
```

### 5. Troubleshooting Patterns

**No traces appearing?**
1. Check Jaeger collector health: `curl http://localhost:14268/api/traces`
2. Check service logs for JAEGER_AGENT_HOST errors
3. Verify network connectivity: `docker exec order-service curl jaeger:6831`
4. Check sampling rate isn't 0

**High memory usage?**
1. Reduce sampling rate
2. Decrease Jaeger retention period
3. Archive old spans to Elasticsearch

**Slow UI queries?**
1. Index traces in Elasticsearch
2. Implement span filtering
3. Lower time range queries
