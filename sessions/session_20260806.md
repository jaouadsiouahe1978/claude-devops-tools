## 🎓 Learning Outcomes

### Multi-stage Builds
- Separate build dependencies from runtime dependencies
- Compile in builder stage, copy only artifacts to runtime
- Result: ~90% smaller images (480MB → 45MB)

### Layer Caching Optimization
- Order Dockerfile instructions from least to most changing
- Place COPY package.json before RUN npm install
- Understand Docker layer caching mechanism
- Save significant rebuild time

### Security Best Practices
- Run containers as non-root users
- Use minimal base images (Alpine Linux)
- Integrate security scanning (Trivy) in workflow
- Keep dependencies up-to-date (npm ci vs npm install)

### Docker Ecosystem
- Docker Compose orchestration
- Health checks (readiness/liveness probes)
- Local registry for development
- Docker API exploration

### Performance Optimization
- .dockerignore for build context size
- BuildKit for parallel layer builds
- Gzip compression in reverse proxy
- Proper orchestration with health checks

## 💡 Key Takeaways

1. **Multi-stage builds are essential for production images**
   - Dramatically reduces image size
   - Maintains functionality and performance
   - Improves security by reducing attack surface

2. **Docker layer caching saves significant time**
   - Understand the importance of instruction ordering
   - COPY package files before RUN install
   - Cache invalidation cascades through all subsequent layers

3. **Security should be built-in from the start**
   - Non-root users prevent privilege escalation
   - Alpine Linux minimizes vulnerabilities
   - Trivy scanning catches known CVEs
   - Regular dependency updates are critical

4. **Tooling and automation are force multipliers**
   - Makefile organizes complex workflows
   - Scripts automate repetitive tasks
   - Docker Compose orchestrates local development
   - Local registry enables realistic testing
